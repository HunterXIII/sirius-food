# AI-ассистент «Сириус.Еды»

Трек F учебной практики. Чат отвечает по меню и FAQ, показывает состав и статус заказов пользователя и предлагает повторить доступное блюдо из истории.

## Запуск

При первом запуске создайте `.env` из `.env.example`, если своего файла ещё нет. Задайте собственный `SECRET_KEY` и добавьте `OPENROUTER_API_KEY` из [настроек OpenRouter](https://openrouter.ai/settings/keys). По умолчанию используется `openrouter/free`. При пустом ключе заказы и история работают, а на запрос генерации чат возвращает сообщение о временной недоступности.

Из каталога проекта выполните одну команду.

```bash
docker compose up
```

Compose соберёт образ с файлами модели, запустит PostgreSQL с pgvector, Redis и RabbitMQ, применит миграции и поднимет API, gRPC-доставку, обработчики событий, Celery, Beat, Flower и Phoenix. PostgreSQL и RabbitMQ используют прежние именованные тома. После изменений кода пересоберите образ через `docker compose up --build`.

- [Swagger](http://127.0.0.1:8000/docs) при `DEBUG=True`.
- [RabbitMQ Management](http://127.0.0.1:15672) с учётными данными из `.env.example` или `.env`.
- [Flower](http://127.0.0.1:5555) для просмотра задач Celery.

## Трейсы в Phoenix

Откройте [Phoenix](http://127.0.0.1:6006) и выберите проект `sirius-food`. После запроса в чат появится `assistant.chat` с режимом ответа и числом источников. Для вопросов по меню и FAQ в нём видны отдельные этапы `assistant.retrieve` и `assistant.openrouter`, их длительность и ошибки. В этапе поиска видны ID и содержимое найденных источников. Векторные совпадения также показывают косинусное сходство. В Input этапа `assistant.openrouter` поле `history` показывает реплики, которые отправили модели, в порядке от старых к новым. Поле `orders` содержит свежий контекст заказов, а `ordered_dishes` — список ранее заказанных блюд. История трейсов хранится в томе `phoenix_data`. Основной трейс показывает текст вопроса и ответа, в том числе текст ответов о заказах. Заголовки авторизации и ключ OpenRouter отдельно в трейсы не записываются.

## Демо в Swagger

1. Зарегистрируйте пользователя через `POST /users/register` и войдите через `POST /auth/login`. Вставьте `access_token` через **Authorize**.
2. Если меню пустое, добавьте пример в локальную БД и запомните полученный ID.

   ```bash
   docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
   INSERT INTO menu_items (name, price, is_available)
   VALUES ('Борщ', 180, true)
   RETURNING id;
   SQL
   ```

3. Вызовите `POST /assistant/chat` с телом `{"message":"Сколько стоит борщ?"}`. В `sources` видно, какие данные из меню использовал чат. Можно также спросить «Что будет, если нет свободного курьера?».
4. Создайте заказ через `POST /orders/create`. Спросите `{"message":"Где мой заказ?"}`, чтобы получить статусы всех активных заказов или последнего, если активных нет, или укажите поле `order_id` для конкретного. Вопрос «Что в моём заказе?» покажет блюдо и количество. Модель формулирует ответы о статусе и составе по данным заказа и истории чата. Запрос чужого заказа даёт тот же ответ, что и запрос отсутствующего заказа. Фраза «Что я заказывал раньше?» покажет до десяти разных блюд из оплаченных или доставленных заказов. По просьбе повторить заказ ассистент предложит последнее доступное блюдо.
5. Передайте `reply_id` в `POST /assistant/replies/{reply_id}/feedback` с телом `{"helpful":true}`. Оценить ответ может его получатель. Для новых ответов оценка также отображается в Phoenix в аннотациях спана `assistant.chat` под именем `helpfulness`. Повторная оценка обновляет аннотацию. Если Phoenix недоступен, оценка остаётся в PostgreSQL.

## Чаты и история

Первый запрос `POST /assistant/chat` с телом `{"message":"Что посоветуешь из меню?"}` создаёт чат и возвращает `chat_id`. Чтобы продолжить тот же разговор, передайте этот ID вместе с новым вопросом. Например, после рекомендации можно спросить «А сколько это стоит?». Ассистент учитывает до четырёх предыдущих ответов модели из этого чата и ищет актуальные данные. В каждом вызове OpenRouter поле `orders` содержит все активные заказы текущего пользователя или последний при отсутствии активных. Передаются номер, блюдо, количество, статус и сохранённая причина отмены, если она есть. Имя, контакты и ID пользователя не передаются.

`GET /assistant/history?chat_id=<id>&limit=20` возвращает сообщения одного чата от новых к старым. Запрос без `chat_id` показывает историю всех чатов текущего пользователя. Для следующей страницы передайте `next_before` из ответа в параметр `before`.

В PostgreSQL сохраняются вопрос, ответ, источники, сценарий ответа, время и оценка. Чаты доступны по JWT владельца. При обновлении ранее сохранённые сообщения объединяются в один чат для каждого пользователя.

## Как работает чат

- Роутер проверяет JWT и передаёт запрос в сервис. Сервис определяет, нужен ли поиск по меню, статус заказа или предложение из истории.
- Репозиторий берёт меню из PostgreSQL и правила из [FAQ](app/modules/assistant/faq.py). При запросе он пересчитывает векторы для новых или изменённых записей. Блюдо, явно названное в вопросе, ищется напрямую в меню. Для остальных вопросов используется векторный поиск по названию, категории и FAQ. Порог косинусного расстояния задаётся через `ASSISTANT_MAX_COSINE_DISTANCE` в `.env`. По умолчанию он равен 0.20. Чем меньше значение, тем строже отбор. Цена и наличие берутся из текущего меню.
- Локальная multilingual-e5-small выдаёт векторы по 384 числа. pgvector сортирует источники по косинусному расстоянию. Лимит выдачи для точного и векторного поиска задаётся через `ASSISTANT_MAX_DOCUMENTS` в `.env`. По умолчанию он равен 6. OpenRouter получает вопрос и найденные факты. Источники возвращаются и клиенту, чтобы ответ можно было сверить. Для вопросов о составе блюд нужны соответствующие сведения в источниках.
- При отсутствии подходящих источников сервис сообщает, что данных мало. Таймаут, ошибка OpenRouter или исчерпание квоты дают ответ с `mode: "fallback"`. В логах API видны идентификатор ответа, сценарий, число источников и время в миллисекундах. Текст запроса, ответа и токены в логи ассистента не записываются.

## Проверка

В проверочном запуске после оплаты и назначения курьера на вопрос «Где мой заказ?» чат вернул «Заказ №1 в доставке.». На вопрос «Что я заказывал раньше?» он ответил «Вы уже заказывали „Борщ“. Хотите повторить?». После изменения цены борща с 180 до 220 ₽ в источниках следующего ответа появилась новая цена.

Автотесты проверяют в том числе передачу найденных фактов в OpenRouter и ответ при исчерпании квоты. В тестах вызов внешней модели подменяется.

```bash
docker compose exec api python -m unittest discover tests -v
```
