# Платёжная интеграция ЮKassa

Трек D учебной практики. Новые заказы оплачиваются через ЮKassa. Когда свободного курьера нет, заказ отменяется с указанием причины, а ЮKassa возвращает полную сумму. Статусы заказа, платежа и возврата видны в Swagger.

## Запуск

1. Создайте [тестовый магазин ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing) и заполните в `.env` параметры `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`. В `YOOKASSA_RETURN_URL` укажите адрес, куда браузер вернётся после попытки оплаты. По умолчанию это локальный Swagger. Если для тестового магазина включена отправка чеков через ЮKassa, для этого демо используйте тестовый магазин без обязательных данных чека.
2. Запустите проект из его каталога. Compose применит миграции и запустит в том числе `payments-worker`.

   ```bash
   docker compose up --build
   ```

3. Настройте публичный адрес `https://<ваш-хост>/payments/webhook`, который перенаправляет запросы на API. Подпишите магазин на `payment.succeeded`, `payment.canceled` и `refund.succeeded` в разделе «Интеграция → HTTP-уведомления». ЮKassa требует порт 443 или 8443 и TLS 1.2+. Для публичного входа достаточно открыть маршрут вебхука. [Документация по уведомлениям](https://yookassa.ru/developers/using-api/webhooks)

## Демо

Для пустой тестовой базы добавьте доступное блюдо.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
INSERT INTO menu_items (name, price, is_available)
VALUES ('Борщ', 180, true)
RETURNING id;
SQL
```

1. Откройте [Swagger](http://127.0.0.1:8000/docs) при `DEBUG=True`. Зарегистрируйте студента, войдите через `POST /auth/login`, передайте `access_token` через **Authorize**. Создайте заказ на доступное блюдо через `POST /orders/create`.
2. В `POST /payments` передайте `{"order_id": 1}`, подставив свой ID, и новый заголовок `Idempotency-Key`, например UUID. Поле `amount` необязательно. Если передать его, сервер сверит сумму с заказом. При `202` получите ссылку позже через `GET /payments/{id}`.
3. Откройте полученную `confirmation_url` и оплатите [тестовой картой ЮKassa](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing). Снова вызовите `GET /payments/{id}`. Успешная оплата имеет статус `succeeded`. Повтор исходного запроса с тем же ключом возвращает прежний ID.
4. **Показ возврата.** Оплатите заказ в тестовой базе без свободных курьеров. В ответе `GET /payments/{id}` появятся `order_status: cancelled`, `cancellation_reason: Свободный курьер не найден` и объект `refund`. Дождитесь `refund.status: succeeded` и покажите полный возврат в личном кабинете ЮKassa.
5. **Показ успешной доставки.** Подготовьте свободного пользователя с ролью `courier`. Для этого зарегистрируйте отдельный аккаунт и назначьте ему роль через `PATCH /users/{id}/role` под администратором. Оплатите новый заказ, дождитесь `delivery_status: in_progress` и возьмите `delivery_id` из ответа. Войдите под назначенным курьером и вызовите `PATCH /delivery/{delivery_id}/complete`. Под студентом снова откройте статус платежа и покажите `order_status: delivered`.
6. **Показ отказа.** Оплатите тестовой картой с имитацией отказа. Заказ останется в `processing`, а у платежа будет `canceled` и причина от ЮKassa, например `insufficient_funds`. Для следующей попытки возьмите новый ключ.

Если в тестовой базе ещё нет администратора, можно напрямую назначить роль тестовому курьеру. Зарегистрируйте его в Swagger и подставьте его `user_id` вместо `42`.

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
UPDATE users SET role_id = (SELECT id FROM roles WHERE name = 'courier') WHERE id = 42;
SQL
```

## Повторы и сверка

При таймаутах и временных ошибках воркер сохраняет повторы с задержками 1, 2, 4 и 8 секунд со случайным отклонением. Повтор использует тот же идентификатор операции в заголовке `Idempotence-Key` ЮKassa. Если все повторы исчерпаны и ID ЮKassa неизвестен, операция переходит в `needs_review`. Для операций с известным ID воркер периодически сверяет статус. Обработанный вебхук подтверждается `200 OK`. Его повтор не запускает повторно ни доставку, ни возврат.

Для поиска операций в `needs_review` выведите `docker compose logs payments-worker`. Сверьте операцию в кабинете ЮKassa по времени, сумме и заказу. Локальный ID платежа есть в метаданных ЮKassa. Для возврата найдите исходный платёж в ЮKassa и проверьте связанные возвраты. Если исходный вебхук удаётся доставить повторно, сервис сверит и применит его. При неизвестном результате очередной запрос с новым ключом может создать вторую операцию. [Правила идемпотентности ЮKassa](https://yookassa.ru/developers/using-api/interaction-format)

## Проверки

```bash
docker compose exec api python -m unittest discover tests -v
```

Нагрузочный сценарий выполняется с PostgreSQL и заглушкой ЮKassa. Он создаёт 100 разных платежей параллельно, затем отправляет 100 копий одного запроса и проверяет число записей в БД и вызовов шлюза. Для запуска укажите URL отдельной тестовой базы PostgreSQL в `PAYMENTS_TEST_DATABASE_URL` и выполните `python -m loadtest.payments` из каталога проекта. Скрипт создаёт временную схему и удаляет её после завершения.

Проверочный прогон с PostgreSQL 15 обработал 100 разных заказов за 0,87 с и 100 повторов одного запроса за 0,34 с. В PostgreSQL и в заглушке ЮKassa сохранилась 101 операция. Эти замеры включают API и базу, но не задержку внешней ЮKassa.
