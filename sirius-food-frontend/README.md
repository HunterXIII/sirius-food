# Сириус.Еда — практическая работа № 8

Витрина Next.js 16 использует FastAPI из родительского проекта. На `/menu` HTML формируется на сервере и по умолчанию обновляется через ISR. `/menu/[id]` рендерит карточку по запросу и возвращает метатеги блюда. `/menu-csr` загружает то же меню в браузере. Все страницы используют одни и те же компоненты карточек.

## Запуск

Из корня репозитория запустите FastAPI и его зависимости. Перед первым запуском подготовьте серверный `.env` по README бэкенда.

```bash
ALLOWED_ORIGINS='["http://localhost:3000"]' docker compose up -d --build api
curl -fsS http://127.0.0.1:8000/menu/items
```

Для CSR нужен разрешённый источник браузера. Команда выше задаёт его на время вызова Compose. Если в серверном `.env` уже есть нужные источники, добавьте к их списку `http://localhost:3000` и запустите Compose без переопределения.

Если меню пустое, добавьте несколько блюд через `POST /menu/items` под ролью `cook` или `admin`. Пример тела запроса — `{"name":"Сырники","price":150}`. Если аккаунта с такой ролью ещё нет, в README бэкенда есть способ наполнить локальную базу через SQL. После прямой вставки выполните `docker compose restart api`, чтобы обновить Redis-кеш.

Затем из корня репозитория запустите фронтенд.

```bash
cd sirius-food-frontend
npm ci
test -f .env.local || cp .env.example .env.local
npm run build
npm start
```

Откройте [меню](http://localhost:3000/menu) или [его CSR-версию](http://localhost:3000/menu-csr). Бэкенд должен отвечать и во время сборки, поскольку Next.js предварительно формирует ISR-страницу. Для разработки можно использовать `npm run dev`.

## Проверка и защита

- **HTML и 404.** Выполните `bash check.sh` из папки фронтенда. Через Ctrl+U найдите название блюда в HTML списка, а в HTML карточки — название и цену. При работающем API запрос к `/menu/999999` возвращает HTTP 404 и страницу «Блюдо не найдено».
- **Загрузка и сбой.** Для демонстрации SSR на каждый запрос остановите фронтенд и запустите `MENU_RENDER_MODE=ssr npm run dev`. Медленный ответ API позволяет увидеть скелетон при переходе к меню. Остановите API через `docker compose stop api` из корня репозитория и откройте `/menu`. После появления ошибки запустите API через `docker compose start api`, дождитесь ответа на `GET /menu/items` и нажмите «Попробовать снова». В production для этого режима нужно задать `MENU_RENDER_MODE=ssr` и при сборке, и при запуске.
- **SEO.** Откройте карточку существующего блюда. В исходном `<head>` есть `title`, `description`, `og:title` и канонический URL. Для публичного запуска задайте `NEXT_PUBLIC_SITE_URL` перед сборкой.
- **ISR.** Запустите обычную production-сборку без `MENU_RENDER_MODE=ssr`. Сразу после открытия меню измените цену через `PATCH /menu/items/{id}` под ролью `cook` или `admin`. После изменения GET списка вернёт новую цену, а HTML списка некоторое время останется прежним. Через 60 секунд после генерации запросите `/menu` для фонового обновления и повторите запрос, чтобы увидеть новую цену.
- **CSR.** В открытом Network перезагрузите `/menu-csr` и найдите запрос браузера к `GET /menu/items`. В исходном HTML загруженных блюд ещё нет.

## Сравнение SSR и CSR

Для сравнения соберите и запустите production-версию в режиме `MENU_RENDER_MODE=ssr`. Отключите кеш браузера во вкладке Network. Сделайте по три полных загрузки каждого маршрута с одинаковым размером окна и настройками сети. Измеряйте время до отрисовки заголовка первой карточки. Его можно увидеть по кадрам в Chrome DevTools → Performance или измерить через Element Timing, добавив первой карточке `elementtiming` до отрисовки.

### Результаты

Локальный FastAPI с PostgreSQL и Redis, Next.js 16.4.5 в production-режиме, Chrome 156 в headless-режиме, окно 1280 × 900, без ограничения сети. Браузерный кеш отключён через Chrome DevTools Protocol. Замер начался от старта навигации и закончился при отрисовке заголовка первого блюда по Element Timing. Перед тремя замерами каждого маршрута сделана одна прогревочная загрузка.

| Метрика | SSR `/menu` | CSR `/menu-csr` |
|---|---:|---:|
| Замер 1, мс | 68 | 60 |
| Замер 2, мс | 36 | 64 |
| Замер 3, мс | 52 | 72 |
| Медиана, мс | 52 | 64 |
| Блюда в исходном HTML | Да | Нет |
| Запрос меню к FastAPI из браузера | Нет | Да |

В этом локальном прогоне первая карточка в SSR появилась на 12 мс раньше по медиане. В SSR заголовки блюд доступны сразу в HTML, поэтому их может прочитать поисковый робот даже без выполнения JavaScript. CSR подходит для экранов, где меню нужно загружать по действиям пользователя или после появления интерфейса. Небольшая разница на локальном стенде может измениться при другой задержке сети или нагрузке.

```text

Итог: PASS=7 FAIL=0
```

В Chrome проверены метатеги карточки в `<head>`, ответ HTTP 404 и восстановление меню по кнопке после перезапуска FastAPI. При двухсекундной задержке ответа API скелетон появлялся до отрисовки списка.

В production-режиме ISR все семь проверок также прошли. После изменения цены сырников через PATCH API сразу показывал 159 ₽, а HTML меню сохранял 150 ₽. При опросе раз в секунду обновлённая цена появилась примерно через 60 секунд.
